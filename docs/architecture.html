How Playwright Studio Works

A local Blazor app that watches you use a website once, writes down what you did, and can do it again on demand. The whole design turns on one idea: the browser is never handed a script to perform — during recording it is handed a pair of eyes.

The central idea

Steps come out, not in

The easiest thing to get backwards. Recording and replay run in opposite directions, and only one of them puts anything inside the page.

While you record, a small script sits inside the web page taking minutes. You drive; it writes down clicked the button labelled Save, typed jane@acme.com into Email. Those notes travel back into the .NET app through a function called __pwsEmit and become the step list on screen.

Replay does none of that. Playwright works the browser from the outside, like a remote control, reading your step list and finding each element itself.

Recording

A watcher in every room

A website is not one room. Every page is a new room, and every iframe — a payment widget, a cookie banner, a sign-in box — is a sealed room of its own.

A watcher planted in one room cannot see into the others, and is thrown out the moment you navigate. So the studio does not plant it per page. It tells the whole browser session: put one of these in every room, including rooms that do not exist yet. That instruction is AddInitScriptAsync, called once on the browser context rather than on a page.

The payoff is the awkward case. You click Sign in, get bounced to Microsoft, sign in, and land back on the app. Four documents, three of them not yours. The watcher is already waiting in each one, in place before the page's own code starts running.

Evidence, not assertion

Two bugs in this app only make sense because the script really does run in every frame. A cross-origin iframe once produced Locator("iframe") resolved to 6 elements — the watcher was inside a frame, naming its own container. And a stray about:srcdoc navigation step appeared because the navigation check was firing in every frame rather than the top one.

Why the toolbar is invisible to itself

Because the watcher lives inside your page, its own REC toolbar would be written down as steps and would inherit your site's CSS. So the toolbar is built in a shadow root — a sealed bubble the page cannot style and the recorder deliberately ignores.

Recording

Choosing how to describe a button

A step has to survive the page changing. That makes "which of the many true descriptions of this element do we write down?" the hardest question in the app.

For every element you touch, the recorder generates a list of candidate descriptions, then throws away any that match more than one thing on the page. What survives is kept in order — the best becomes the step's selector, and the rest are stored as fallbacks the runner can try later.

The counter-intuitive rank

Machine-generated ids sit below role and text on purpose. #mudinput08267ls7 is unique, precise, and worthless — it changes the next time the component renders. A button described as "the one labelled Save" outlives a rebuild; one described by a generated id does not.

Replay

Finding it again, and saying why not

The page you replay against is never quite the page you recorded. Most of the runner is about closing that gap, and explaining itself when it cannot.

A bare Timeout 10000ms exceeded tells you nothing you can act on. So when a step fails, the runner goes back and asks the page what was actually true — and reports which of four situations it hit.

The runner also follows tabs the journey opens, accepts browser confirm dialogs, and falls back from a dropdown option's value to its visible label.

The parts

What talks to what

One process. The user interface is a web page served by the same app that drives the browsers, and everything it remembers is plain files on your disk.

One more output

Because every step already carries a screenshot and a written description, the same recording drafts a user manual — numbered instructions with pictures, editable, printable to PDF. Nothing extra is captured for it; it is the run report read for a different audience.
